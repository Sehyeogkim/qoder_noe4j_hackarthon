03 / GRAPH SCHEMA

장면은 보관하고,
관계를 검색한다.

조건은 실행별 snapshot으로 저장합니다. 같은 물체의 서로 다른 시점 상태가 섞이지 않게 합니다.

제안 스키마 / 6 NODE TYPES노드를 선택하면 필드 표시
← OF_TASK ─
HAS_CONDITION ↓HAS_ATTEMPT ↓SUPPORTED_BY ↓
RESULTED_IN ↓
Episode E-002 ── RECOVERY_OF → Episode E-001

복구 성공도 해당 조건에서의 관측입니다. 전역적인 성공 규칙으로 승격하지 않습니다.

NODE CONTRACT

Neo4j 조회 초안 조건으로 후보를 찾고, 복구 실행까지 연결
MATCH (failed:Episode)-[:OF_TASK]->(:Task {kind: $task_kind}),
      (failed)-[:HAS_CONDITION]->(c:Condition),
      (failed)-[:HAS_ATTEMPT]->(:Attempt)-[:RESULTED_IN]->(:Outcome {success: false}),
      (recovery:Episode)-[:RECOVERY_OF]->(failed),
      (recovery)-[:HAS_ATTEMPT]->(a:Attempt)-[:RESULTED_IN]->(:Outcome {success: true})
WHERE c.predicate = 'obstacle_in_transfer_corridor'
  AND c.value = 'true'
  AND failed.id IN $snapshot_episode_ids
  AND recovery.id IN $snapshot_episode_ids
RETURN failed.id, recovery.id, a.instruction
LIMIT 5

후보 조회 초안입니다. 후보의 전체 조건·근거를 읽고 현재 관측과 재검증해야 하며, 이 조회만으로 명령을 적용하지 않습니다.
