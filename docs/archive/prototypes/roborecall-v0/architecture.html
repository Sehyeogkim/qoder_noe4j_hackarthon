추가 관측·추론·재시도 예산과 평가용 메모리 snapshot을 고정합니다.
  1. 기본 VLA 실행기존 작업에서 정상 작동하는지 확인
  2. 수동 명령 변화출력 숫자뿐 아니라 궤적·작업 결과 비교
  3. 경험 연결메모리 없이 명령을 수정하는 agent와도 비교

  
ACTION 실행 계약
단일 action: 같은 지시로 VLA 반복 실행 → 이벤트에서 agent 재판단. Chunk: k개 실행 후 재관측. 새 명령이 생기면 남은 chunk를 폐기하고 재추론할지 명시해야 합니다. k는 모델·환경을 정한 뒤 고정합니다.
근거와 용어의 범위
Extrinsic / intrinsic은 이 설계에서 정의한 경계입니다. 통일된 VLA 분류 체계로 주장하지 않습니다. 화면의 agent trace와 JSON은 설계 예시이며 실측 로그가 아닙니다.
  • OpenVLA 공식 README — 현재 모델은 action 생성에 학습됐으며 기존 텍스트 생성 경로가 작동하지 않는다고 명시.
  • 공식 forward / predict_action 코드 — hidden states 출력 인터페이스와 action token 해독 경로. 이것이 tool 사용 능력을 보장하지는 않음.
Skill은 미리 구현된 기능 또는 검증된 명령 절차를 의미합니다. 에이전트가 절차를 메모리에 추가해도 VLA에 새로운 운동 능력이 생겼다고 해석하지 않습니다. chunk 정책으로 바꾸면 실행 버퍼·재계획 주기도 계약에 추가해야 합니다.
